# SPEC GJ-slide-core-01 — SLIDE CORE: classic core

> **Status:** Draft
> **Depends on:** SPEC 06, SPEC 07, SPEC 08, SPEC 11
> **Date:** 2026-11-13
> **Objective:** Create SLIDE CORE, a 4x4 merge-slide puzzle with a move-count-free score and a game over when no moves remain, as a typed engine played at `/games/slide-core/play` with its own leaderboard.

## Why this spec exists

SLIDE CORE is a new game from the game jam. The pending entry in `references/game-suggestions-todo.md` says it is "close to a known clone, keep original art/naming". This spec therefore defines every visual and naming choice in the platform's own terms: the title, the cover, the tile palette and the copy are original, and no clone branding is reused.

The game is a pure puzzle: a 4x4 board, one move per key press, and a score that only grows from merges. It needs no assets and no sound, so it does not bootstrap any shared module. It fits the registry from SPEC 08 with one engine, one entry and one seed row.

The second phase, `02-slide-core-rush.md`, is a timed variant. It is a separate catalog row because scores are keyed by `game_id` only, so a timed run and a classic run would otherwise share one leaderboard with incomparable numbers.

## Scope

**In:**

- Seed migration `supabase/migrations/20261113120000_seed_slide_core.sql` with the `games` row (`id = 'slide-core'`, `title = 'SLIDE CORE'`, `category = 'PUZZLE'`, `cover = 'cover-slide'`, `color = 'cyan'`, `plays = 0`, `sort_order = 6`).
- Typed engine in `lib/games/slide-core/` (no React, no globals) with: 4x4 board, slide in four directions, merge once per tile per move, one spawned tile per valid move, top tile and free-cell tracking, game over when no moves remain, and restart.
- Score = sum of every merge's new value, clamped to `9,999,999`. No move counter.
- Slide animation, merge pop and spawn scale-in drawn on the canvas (visual only; the logic is instant).
- Classic skin in `lib/games/slide-core/skins.ts` (the default).
- Registry entry: HUD TOP and FREE, controls legend, touch layout (four arrows), aria label.
- New cover class `cover-slide`, designed with `/frontend-design`.

**Out of scope (for future specs):**

- The timed variant and its catalog row (`02-slide-core-rush.md`).
- Undo, hints, a move counter and any move-based penalty.
- A win state at any tile value. The run is open-ended.
- Sound and the shared audio module.
- The `neon` and `retro` skins. They are generated by `/skin-designer slide-core`, not by this spec.
- Gamepad controls and anti-cheat or server-verified scores.
- Schema changes, a plugin system beyond the registry, redirects.
- Any change to `references/`.

## Data model

No schema change: `scores` and `submit_score` are generic per `game_id`.

Seed:

```sql

insert into public.games (id, title, short, long, category, cover, color, plays, sort_order)
values (
  'slide-core',
  'SLIDE CORE',
  'Slide and merge numbered tiles on a 4x4 board.',
  'Slide every tile on the board and merge equal numbers into their double. Every merge scores its new value and there is no move counter. When the board fills and no two neighbours match, the run is over.',
  'PUZZLE',
  'cover-slide',
  'cyan',
  0,
  6

```

Types:

```ts
// lib/games/slide-core/types.ts
export type SlideCoreState = "playing" | "gameover";
export type Direction = "left" | "right" | "up" | "down";

export type SlideCoreSnapshot = {
  score: number; // 0..9_999_999, clamped
  top: number; // largest tile value on the board, 0 before the first spawn
  free: number; // empty cells, 0..16
  state: SlideCoreState;
};

export type SlideCoreOptions = GameOptions & { mode?: "classic" | "rush" }; // mode is used by 02 only

export type Tile = {
  id: number; // stable across slides; a merge keeps the survivor's id
  value: number; // 2, 4, 8… (2^k)
  row: number;
  col: number;
  from: { row: number; col: number } | null; // slide origin while animating
  anim: "none" | "slide" | "pop" | "spawn";
  t: number; // seconds left in the current animation
};

export function createSlideCoreGame(
  canvas: HTMLCanvasElement,
  callbacks: GameCallbacks<SlideCoreSnapshot>,
  options: SlideCoreOptions,
): GameEngine;
```

Files in `lib/games/slide-core/`:

- `types.ts`: the types above.
- `constants.ts`: values below and `PALETTE`.
- `logic.ts`: pure board functions (no canvas, no timers): `slideGrid`, `spawnTile`, `hasMoves`, `snapshotOf`. The grid is a flat `number[16]` (index `row * 4 + col`, `0` = empty) used by the rules and tested by the criteria.
- `skins.ts`: `SKINS` with the `classic` skin only (see Decisions).
- `engine.ts`: tile list, animations, input, loop, draw and `createSlideCoreGame`.

Constants (`constants.ts`):

```ts
export const W = 800;
export const H = 600;
export const SIZE = 4; // cells per side
export const BOARD = { cell: 104, gap: 12, left: 162, top: 62 }; // 4 × 104 + 5 × 12 = 476 px, centered
export const START_TILES = 2;
export const SPAWN_VALUES = { two: 2, four: 4, chanceFour: 0.1 };
export const SLIDE_TIME = 0.08; // s, visual slide only; logic is instant
export const POP_TIME = 0.12; // s, merged tile scales 1 → 1.12 → 1
export const SPAWN_TIME = 0.12; // s, new tile scales 0 → 1
export const MAX_DT = 0.05; // s, platform cap
export const MAX_SCORE = 9_999_999;
export const RADIUS = 8; // px, tile corner radius
```

Other palette entries: background `#0a0a0f` (`--bg`), empty slot `#15151f`, board frame `rgba(0, 245, 255, 0.18)` (`--line`). Digit size by length: 1–2 digits `44px`, 3 digits `36px`, 4 digits `28px`, 5 or more `20px`, always `bold` with `"JetBrains Mono", monospace`.

Conventions:

- Logical field `W = 800`, `H = 600`, origin top-left. It is 4:3, so it fills the `.crt-screen` with no letterbox. Backing store scaled by `devicePixelRatio` (cap 2).
- Time in seconds, `dt` capped at `MAX_DT`. `resume()` and `restart()` reset `lastTime`.
- Controls: `←` `→` `↑` `↓` or `A` `D` `W` `S` slide the whole board one step. One key press is one move (`pressed()`, not `pressedOrRepeat()`), so holding a key does not slide repeatedly. If several directions are pressed in the same frame, the order is left, right, up, down.
- `preventDefault` only for the four arrow codes, so the page does not scroll. `Space`, `P`, `Esc` and `M` are not bound by the engine.
- `onChange` fires only when `score`, `top`, `free` or `state` differs from the last emitted snapshot. The last emitted snapshot starts as the registry's `initialSnapshot`.
- `onGameOver(score)` fires once per game over.
- Canvas draws only the board frame, the empty slots and the tiles with their digits. It draws no score, TOP, FREE, GAME OVER or restart text.
- Logic is instant. Tiles animate toward their new cell for `SLIDE_TIME`, so input is never blocked by an animation.

## Implementation plan

1. **Seed migration.** Write `20261113120000_seed_slide_core.sql`, run `npm run db:push`, then `npm run db:types`. Check with Supabase MCP `execute_sql`: `games` has `asteroids`, `tetris`, `arkanoid`, `snake`, `toadroad` and `slide-core`, and `scores` has no `slide-core` rows. Add `'slide-core'` to the seeded list in `supabase/checks/verify-prod.sql` and keep the count in sync. Restart the dev server if the cached list does not show it. Check: `/games` lists SLIDE CORE, and `/games/slide-core/play` shows "NOT PLAYABLE YET".
2. **Cover.** Add the `cover-slide` class to `app/globals.css`, designed with `/frontend-design`: a dark radial background (`#0a0a18`) with a 4x4 grid of small cyan and green tiles, using only palette tokens. Check: the card on `/games` and the home rail show the cover with no broken layout.
3. **Types, constants, skins.** Create `types.ts`, `constants.ts` and `skins.ts` (classic only). Check: `npm run lint` passes and no file imports React.
4. **Pure rules.** In `logic.ts`, write `slideGrid(grid, dir) → { grid, gained, moved }`: for each line in the direction, compress the non-zero values toward the leading edge, merge each adjacent equal pair once from the leading edge, and add each merge's new value to `gained`. Write `spawnTile(grid, rng)` (one tile in a random empty cell, `2` with 90% and `4` with 10%), `hasMoves(grid)` (a free cell or two equal neighbours) and `snapshotOf(grid, score)`. Check: `npm run build` passes, and the worked examples in the acceptance criteria hold when `slideGrid` is called from a scratch script outside the repo.
5. **Engine.** In `engine.ts`, add `createSlideCoreGame`: tile list from the grid, spawn of `START_TILES` tiles, `applyMove` (valid move only: slide, spawn, check game over), score with the clamp, animations, rAF loop with the `dt` cap, `createInput` with the four arrow codes prevented, `draw` (board, slots, tiles, digits), `onChange` on change only, `onGameOver` once, and `pause`, `resume`, `end`, `restart`, `destroy`. Check: `npm run build` passes and the engine runs when mounted by a scratch page.
6. **Registry entry.** Add `slide-core` to `lib/games/registry.ts`: `initialSnapshot` (`score 0`, `top 0`, `free 16`, `state "playing"`), `hud` returns TOP (`String(top)`, yellow) and FREE (`free`, cyan), `controls` (`← ↑ ↓ →` and `W A S D`, both "Slide"), `ariaLabel: "Slide Core game"`, `touch: { dpad: ["up", "down", "left", "right"], buttons: [] }`. Check: `/games/slide-core/play` runs the real game with no console errors.
7. **HUD and cover polish with `/frontend-design`.** Check the TOP and FREE stats and the controls legend at 375 px, and adjust only what looks broken. Check: the legend fits without horizontal scroll.
8. **Verification pass.** Run `npm run lint` and `npm run build`, then every acceptance criterion below, including the regression for the other games.

Before writing code, read `node_modules/next/dist/docs/` for Client Components, dynamic `import()` and lazy loading, and `'use cache'` / `cacheTag` for the cached game list.

## Decisions

- **Yes:** typed engine in `lib/games/slide-core/`, as with the other games. No globals, clean mount and unmount, typed under `strict`. Provided (game jam).
- **No:** iframe or `next/script` port. No reference code exists; the engine is written from the rules. Agent's choice (game jam).
- **Yes:** platform HUD and GAME OVER modal. The canvas draws only the board. TOP and FREE are HUD stats. Agent's choice (game jam).
- **Yes:** `id = slide-core`, title `SLIDE CORE`, `PUZZLE`, `cyan`. Provided (game jam).
- **Yes:** `cover-slide` as a new class, designed with `/frontend-design`. The existing covers are taken by other games. Agent's choice (game jam).
- **Yes:** `sort_order = 6`, the next free value after `lane-surge`'s planned 5. Agent's choice (game jam).
- **Yes:** 4x4 merge-slide rules as described: one merge per tile per move and a spawn after each valid move. Provided (game jam).
- **Yes:** score is the sum of every merge's new value, with no move counter. Provided (game jam: move-count-free score).
- **Yes:** game over only when no moves remain. Provided (game jam).
- **No:** a win state at a target tile. A run must stay open-ended so better players always score more, and a target would make every winner tie. Agent's choice (game jam).
- **No:** undo, hints or move penalties. They change the puzzle and the leaderboard meaning. Agent's choice (game jam).
- **Yes:** spawn values 2 (90%) and 4 (10%). These are the standard odds of the genre and the simplest ones to explain. Agent's choice (game jam).
- **Yes:** one key press is one move (`pressed()`), so holding a key does not run the board. This keeps every move deliberate and the same on touch. Agent's choice (game jam).
- **Yes:** logic instant, animation visual only (`SLIDE_TIME` 0.08 s). Input is never blocked, and a fast player never waits. Agent's choice (game jam).
- **Yes:** original naming and palette. The title, copy, cover and tile colors are not taken from any existing clone, and the win value of such clones is not used. Provided (game jam: keep original art and naming).
- **Yes:** `skins.ts` with `classic` only in this spec. The `neon` and `retro` skins are added by `/skin-designer slide-core` as the contract requires (`/spec-impl-game` runs it). Agent's choice (game jam).
- **Yes:** no sound. The first game with no audio needs no shared module, and the `M` key stays free. Agent's choice (game jam).
- **Yes:** `verify-prod.sql` lists the new seed, as the runbook requires for every migration. Agent's choice (game jam).

## Risks

| Risk                                                     | Mitigation                                                                                                                 |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| StrictMode double mount starts two loops                 | `destroy()` cancels the rAF and detaches input; `GameCanvas` already guards with `cancelled`.                              |
| Input steals keys from the modal                         | Shared input ignores `input`, `textarea` and contenteditable targets; the initials criterion covers `W A S D`.             |
| Arrow keys scroll the page                               | `preventDefault` only for the four arrow codes while playing.                                                              |
| Blurry digits on high-DPI                                | Backing store scaled by `devicePixelRatio` (cap 2).                                                                        |
| Font not loaded when the first frame draws               | `document.fonts.load` for the digit font before the first draw; fallback is `monospace`, never a blank tile.               |
| Score clamp hides a bug                                  | The clamp is a last resort; criteria check the worked examples so merges are counted right before it applies.              |
| Tile animation id mismatch after a merge                 | A merge keeps the survivor's id and drops the other; the criteria check that the pop plays once and no tile is duplicated. |
| Two tiles overlap during a slide                         | Logic is instant; draw interpolates each tile from `from` to its cell, so overlap lasts at most `SLIDE_TIME`.              |
| Cover class clashes with another game                    | `cover-slide` is checked against `globals.css` before writing; the rush variant uses `cover-slide-rush`.                   |
| Clone branding creeps in through naming or art           | Original title, copy, colors and cover; reviewed against the criteria and the Decisions above.                             |
| Cached game list does not show the new row until rebuild | Plan step 1 restarts the dev server; production needs a rebuild or `games` tag invalidation.                               |
| Scores forgeable until Auth                              | Accepted in SPEC 07.                                                                                                       |

## What is **not** in this spec

- The timed variant and its catalog row (`02-slide-core-rush.md`).
- Undo, hints, a move counter and move penalties.
- A win state at any tile value.
- Sound and the shared audio module.
- The `neon` and `retro` skins (`/skin-designer slide-core`).
- Gamepad controls, anti-cheat, server-verified scores and Auth.
- Schema changes, a plugin system beyond the registry, and redirects.
- Any change to `references/`.

Each one of those, if it lands, goes in its own spec.
